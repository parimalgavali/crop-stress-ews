# ADR 0033: Automated accessibility checks in CI

Status: Accepted (US-36, Issue #79)

## Context
The site claims to be simple for anyone, including people who read poorly. It has read-aloud,
big buttons, and colour plus words. Until now that was only checked by hand.

## Decision
- `web/e2e/a11y.spec.ts` runs axe-core (`@axe-core/playwright` 4.10) with the WCAG 2.0/2.1 A and
  AA rules on four screens: the replay risk card and the full Live card (lights, chart, soil,
  growth stage, "I checked it"), each in English and German.
- It runs in the existing Playwright step of the CI `web` job, so any new violation fails the
  PR. No separate job and no Lighthouse are used. Lighthouse adds a heavy, flaky Chrome audit
  and finds the same axe rules.
- Only the map canvas is excluded. It is a picture of the fields, and every field is also
  selectable in the "Field" list.
- Fixed now:
  - The map container had `role="img"` but contains buttons and links (`nested-interactive`).
    It is now `role="region"`.
  - The MapLibre credit links were told apart from their text by colour only
    (`link-in-text-block`). They are now underlined.

## Consequences
- Automated checks catch about a third of WCAG problems. Whether the plain words are
  understood, read-aloud quality, and real screen-reader use still need a manual test with
  users.
